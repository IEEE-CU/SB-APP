### Can any /api/ response be cached by a service worker?
- From the code: **no service worker exists, so none can store or serve a response.** That answers the SW question for the inspected tree.
- Browser HTTP cache / shared caches are a separate matter: the backend sets no `Cache-Control` of its own. Express defaults add a weak `ETag` on JSON responses; helmet 7/8 defaults do not set `Cache-Control` either (not confirmed against the installed version; needs a runtime header check). Without `Cache-Control: no-store` (or `private, no-cache`), a browser/intermediary may heuristically cache GET JSON that has no `Last-Modified`... practical risk is low but the financial and personal endpoints do not currently state "never cache". **Recommendation (for owner decision, not done):** add `Cache-Control: no-store` to `/api/v1` responses (or at least financial/personal routes) before any PWA is introduced. That is a code change, outside this task.
- If a PWA is added later, requirement R1: runtime-cache rules must exclude `/api/` and `/socket.io/` entirely (NetworkOnly), and the shell precache must be static assets only.

### Where the two backend example files disagree
1. Different variable sets: the root-level backend file has the operational/security variables (MONGODB_URI, JWT_SECRET, JWT_EXPIRES_IN, TRUST_PROXY, ENABLE_CLUSTER, DB_*); the `src/` file has none of the required ones (no MONGODB_URI, no JWT_SECRET) and instead has feature placeholders. A new developer copying the `src/` file would hit the "Missing required environment variable" exit.
2. Only `backend/.env.example` is the correct template for `dotenv` and for server start-up validation; `src/.env.example` is misleading by location and content.
3. Same name, different defaults: `NODE_ENV=development` and `PORT=5000` agree; `GEMINI_API_KEY` blank in src, placeholder string in backend. GEMINI_MODEL only in src.
4. Frontend example uses `http://localhost:5000/api/v1` (absolute, cross-origin, requires CORS and FRONTEND_URL), while the code default and the Vite dev proxy use the relative `/api/v1` (same-origin). Not a conflict in code, but the example steers developers to the cross-origin route.
5. README/charter mention a root `.env.example`: none exists.
